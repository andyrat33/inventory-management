# UX Audit — Inventory Management App

**Reviewer:** ux-reviewer · **Date:** 2026-09-07 · **Scope:** `client/src` (Vue 3 + Vite frontend), static code review.

## Summary

The app has a clean, consistent visual design system but significant usability and accessibility gaps. The most serious functional bug: **`Dashboard.vue` references `<PurchaseOrderModal>` which is never imported or registered and does not exist as a file** — the "Create PO" / "View PO" buttons on the dashboard shortages table do nothing (UX-1). Beyond that, the app has **zero responsive design** — there is not a single `@media` query in the codebase, the sidebar and 4-up filter bar are fixed-width, and every data table plus every custom chart will overflow or clip on tablet/phone widths (UX-2, UX-3). **Accessibility is largely absent**: no modal has Escape-to-close, focus trapping, focus return, or `role="dialog"`/`aria-modal`; the profile and language dropdown menus are built with `@mousedown.prevent` so their items cannot be activated by keyboard at all (UX-6); clickable table rows and clickable `<td>`s are not keyboard-reachable across five views (UX-7); icon-only buttons mostly lack accessible names (UX-8); form controls in the filter bar are not associated with their `<label>`s (UX-9); tables use no `<th scope>` (UX-10); and muted text at `#94a3b8` fails WCAG AA contrast (UX-11). Error handling is inconsistent — background actions (`loadTasks`, `createTask`, `deleteTask`, `toggleTask`, `loadRestockingOrders`) swallow failures into `console.error` with no user feedback (UX-12), and the shared filter bar re-triggers a full-screen "Loading…" state that blanks the table on every filter change (UX-13). `Reports.vue` and `Backlog.vue` are un-internationalised, `Backlog.vue` ships a `✓` emoji in the UI (violates the project's no-emoji rule) and is not even wired into the router, and `Reports.vue` runs `console.log` inside template-invoked methods so it logs on every render (UX-14, UX-15, UX-16). Several date formatters call `new Date(...).toLocaleDateString()` with no validity check and will render "Invalid Date" to users (UX-17).

Severity legend: **Critical** = broken feature / legal exposure · **High** = blocks a user group or common task · **Medium** = friction / degraded experience · **Low** = polish.

## Cross-angle notes for the challenge round

- **UX-1** (missing `PurchaseOrderModal`) and **UX-16** (`console.log` in render) will likely also surface in the perf/security reviews — I hold UX-1 at Critical on _user impact_ (dead primary action) regardless of how they frame it.
- **UX-11 / UX-23** (contrast, focus-visible) carry **accessibility/legal exposure** (WCAG 2.1 AA, ADA/EN 301 549) that a pure perf or security lens will under-rate.
- **UX-12** overlaps any security finding about error handling — my angle is the _silent data loss_, theirs may be _information disclosure_; both fixes are the same `catch` block.
