## False positives / over-rated — none

I found no security or performance finding that I'd call a false positive or that is over-rated for its stated axis. Notes:

- **PERF-15** (CSV export) is correctly self-assessed as "no issue" — I concur; my UX-only concern there is the missing post-download confirmation toast (UX-... polish, Low).
- **SEC-5** (Infinity/NaN budget → 500): correctly Low. Confirming from the UI side that it is **not reachable through the app** — the Restocking slider is `min="0" max="500000" step="5000"` (`Restocking.vue:13-21`), so only a direct API caller can trigger it. That supports, not weakens, the Low rating.
- **SEC-6** (CSV formula injection): Low is right. The one input that will eventually matter is user-entered task titles (`TasksModal.vue`), which currently never reach the CSV path — worth a note in the fix so the escaping lands before task data is ever exported.
- **SEC-1 / SEC-2 / SEC-3**: the "demo, mock data" framing is consistent with what I saw on the frontend (no login route, `isAuthenticated = ref(true)`, no guards in `main.js`). No challenge to the security severities.

## Accessibility / legal exposure the other lenses don't weight

For the synthesis: my UX-6 (dropdown menus keyboard-dead), UX-7 (clickable rows keyboard-unreachable), UX-8 (unnamed icon buttons), UX-9/UX-10 (unlabelled form controls / no `<th scope>`), UX-11/UX-23 (contrast + invisible focus), UX-18 (modals: no Esc, no focus trap, no `role="dialog"`), UX-22 (collapsed sidebar icons unlabelled — and collapsed is the default under 1024px) are **WCAG 2.1 AA failures**. If this app is ever used by a public-sector or enterprise customer, that's procurement-blocking / ADA-exposure territory — a category neither the security nor the performance review scores. I'd carry UX-6, UX-7, UX-18, and UX-22 into the action plan at **High**.
