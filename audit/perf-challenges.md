## Severity changes I propose

| Peer ID                                                                  | Their severity                                         | My proposed severity                                              | Concrete rationale (performance lens)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ------------------------------------------------------------------------ | ------------------------------------------------------ | ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **UX-16** — `Reports.vue` `console.log` in template-invoked methods      | **Low** ("minor perf"; they explicitly deferred to me) | **Medium** on the UX board / **High** on mine (this is my PERF-1) | `formatNumber` is bound in the template and evaluated ~30×/render (quarterly table 2×/row × 4, MoM table 3×/row × ~9, summary tiles ×2, chart title); `formatMonth` ~20×; `getBarHeight` once/bar. Each does a synchronous `console.log` that stringifies its args and writes to the console ring buffer. With DevTools open this is _measurably_ janky and blocks the render commit; it is also shipped debug code in a demo that will be screen-shared. Not "minor" — it is the single most measurable frontend cost in the app precisely because the dataset is otherwise tiny. Raise it. |
| **SEC-4** — Unbounded request bodies / no rate limit → memory-growth DoS | **Low/Medium**                                         | **Medium** (settle it, don't leave it at Low)                     | The perf lens reinforces this: every `GET /api/tasks` returns the _entire_ `tasks` list unpaginated (`main.py:435-438`), and `generate_task_id` (`:429-433`) and `generate_restocking_order_id` (`:235-239`) do an O(n) `max(int(...) for ...)` scan on every create. An attacker (or a runaway client) that inflates these process-global lists degrades every subsequent request linearly, not just RSS. Combined with no cap and no pagination this is a real availability slope, so Medium is the right floor.                                                                           |
